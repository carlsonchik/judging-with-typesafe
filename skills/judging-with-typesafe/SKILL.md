# Суждения через TypeSafe Jev

Jev — модель «System One»: не генерирует текст, а отвечает на **типизированный вопрос** о переданном
состоянии. Возвращает числа и распределения, по которым код ветвится. Проверено на живом API 17.09.2026.

## Главный принцип: «не знаю» — это результат, а не провал

Собственная формулировка TypeSafe: *«Если интеллектуальная система — человек или машина — не может
выразить честную неопределённость, такой системе нельзя доверять.»*

Поэтому **ответ 0.30–0.70 не интерпретируется**. Это явное `uncertain` → человеческая проверка.
Попытка выжать из этой зоны вердикт — главная ошибка при работе с инструментом (проверено на себе).

Три режима, как советует их документация:

| Значение | Что делать |
|---|---|
| > 0.70 | действовать автоматически |
| 0.30–0.70 | **не действовать**: уточнить, пометить для проверки человеком |
| < 0.30 | не действовать, вернуть причину |

Пороги зависят от цены ошибки: для необратимого решения порог выше.

## Что умеет и что нет (проверено)

| | Jev | обычная LLM |
|---|---|---|
| возвращает | число, распределение, `confidence` | текст для интерпретации |
| воспроизводимость | **разброс 0.004–0.014** на 8 прогонах; у LLM — заметно выше даже при temperature 0 | — |
| стоимость | ~306 токенов вход, 20 выход | тысячи токенов |
| скорость | ~2 с на запрос | десятки секунд |
| **различение качества текста** | **НЕ умеет** — наукообразный абзац получил 0.74, абзац учебника 0.48 | тоже не умеет |
| проверка фактов | не умеет: выдуманный источник 0.80 против 0.87 у настоящего | не умеет |

**Что действительно различает:** вопрос *«можно ли проверить утверждение фрагмента, не обращаясь
к автору?»* дал разрыв +0.34 между проверяемым и наукообразным текстом — но **крайние случаи
разделяются, середина шкалы шумит**. Для философской прозы этот вопрос не работает: она требует
обращения к автору по своей природе.

## Как строить рубрику (а не один вопрос)

Их собственный паттерн (self-consistency cookbook): **рубрика из нескольких Noul-вопросов, один вызов
на всю рубрику**, и явная зона неопределённости. Один вопрос всегда смещает оценку — например
«автор заявляет больше, чем обосновывает?» дало абсурду 0.53, то есть вопрос тянет за собой
суждение, которого в тексте нет.

Рабочая рубрика для оценки фрагмента текста:

1. «Фрагмент называет конкретные объекты и операции или только описывает значимость темы?»
2. «Можно ли проверить утверждение фрагмента, не обращаясь к автору?»
3. «Если убрать оценочные слова, останется ли проверяемое содержание?»
4. «Фрагмент сообщает что-то определённое или создаёт впечатление глубины?»

**Отброшенные вопросы** (проверены, дают отрицательный разрыв или шум):
«указан способ проверки?», «понятно, откуда числа?» — в учебнике их тоже нет, различения не дают.

## Калибровка обязательна

Перед применением на новом материале: прогнать **контрастную пару** — заведомо строгий текст
(учебник, спецификация) и заведомо наукообразный-пустой — и проверить, что вопрос даёт разрыв.
Без этого шага числа выглядят точными, оставаясь случайными.

## Использование

```bash
python3 scripts/typesafe.py noul   "состояние" "вопрос"                 # вероятность «да» 0..1
python3 scripts/typesafe.py choice "состояние" "вопрос" -o а б в        # выбор + вероятности + confidence
python3 scripts/typesafe.py score  "состояние" "вопрос" -o низко средне высоко   # criteria ТОЛЬКО списком
python3 scripts/scan_text.py текст.md --mode verify --min-len 400        # карта по абзацам
```

Режимы `scan_text.py`: `verify` (проверяемость — основной), `rubric` (четыре вопроса выше),
`claim`, `source`.

Ключ: `TYPESAFE_API_KEY` (scripts читают её через свежий `zsh -lic`, поэтому работают и когда
приложение запущено со старым окружением).

## Двойной счёт

Jev оценивает **предъявленное**, а не мир: он не спорит с контекстом и не добавляет того, чего в нём нет.
Поэтому не перекладывать на него проверку ссылок, фактов, институциональную подотчётность
и различение «строгое знание / наукообразная пустота» — для этого нужна сверка с миром.
